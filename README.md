# M5PaperDashboard

一个基于 **M5Stack M5Paper**(540×960 竖屏电子墨水屏)的系统状态仪表盘。上位机通过 USB 串口
推送系统数据,M5Paper 将其渲染为三个铺满全屏的区块——**MEMORY / TEMPERATURE / POWER**,每个区块
包含标签、进度条和一个大号数值。**G26** 上的继电器驱动散热风扇,屏幕上的向上箭头指示是哪个指标
触发了风扇。

## 功能特性

- **三个全屏区块**,每个 540×320 px,铺满整块屏幕、不留未刷新边框,因此长时间运行也不会在边缘
  积累永久残影。
- **分级刷新**:平时只重刷数值真正变化的区块,用 `REFRESH_MODE_KEEP`(GL16,闪烁较轻);
  每累计 `GC16_EVERY`(默认 30)次、或距上次深刷超过 `GC16_MAX_AGE_MS`(默认 30 分钟),
  改用 `REFRESH_MODE_FULL`(GC16 反色全刷)把三块一起深刷,清掉累积残影。
- **抗褪色兜底(按块计时)**:某一块超过 `REFRESH_MAX_AGE_MS`(默认 10 分钟)没被驱动过,即使数值
  完全没变也会强制刷它一遍。计时必须**逐块**(`lastPushMs[i]`)——若挂在"整屏多久没刷过"上,内存
  频繁跳动时该计时永远被刷新、兜底从不触发,而反白恰恰发生在长期不重绘的那一块上。
  这条只会**增加**刷新、不影响数据实时性,作用是给墨水漂移的累积封顶。
- **降温(治本)**:反白的实测根因是面板下方芯片区的**局部自发热**,不是刷新串扰(热像实测热点
  33.7 °C、比室温高 7.4 °C,而屏幕其余部分仅高 0.7 °C,且三块刷新方式相同却只有下半部发白)。
  对策见下方[降温设计](#降温设计)。
- **断连状态**:若 30 秒内没有收到数据包(或开机后首包到达之前),所有数值显示 `-`、进度条归零。
- **伪粗体文字**(内置 TTF 只有一种字重,通过在微小偏移处叠印来加粗笔画),便于一米开外也能看清。
- **滞回风扇控制**(G26),温度/功率组合触发。
- **向上箭头指示**,与风扇启停同步,绘制在高于关闭阈值的那一行(温度和/或功率)。
- **内置 SHT30**(I²C 0x44,SDA=G21 / SCL=G22),可按需上报环境温湿度。

## 硬件

| 项目 | 说明 |
|---|---|
| 主板 | M5Stack M5Paper(ESP32,IT8951 电子墨水驱动) |
| 风扇 / 继电器 | M5Stack 三线继电器模块,接 **PORT.B(G26)**,5V 取自板上 EXT 升压。若继电器为低电平触发,把 `FAN_ACTIVE_LOW` 设为 `1`。 |

## 降温设计

反白是热出来的,所以真正的解法是降低那块热点的功耗,而不是靠刷新策略去掩盖:

| 措施 | 配置项 | 说明 |
|---|---|---|
| IT8951 空闲休眠 | `EPD_IDLE_MODE`(默认 `2`=Sleep) | `M5EPD::begin()` 之后 IT8951 会**一直停在 `SYS_RUN`**,整晚不刷屏也在空转发热——热点即由此而来。改为刷前 `Active()`、刷完休眠。`1`=StandBy(保守),`0`=不休眠(原行为) |
| 只刷变化的块 | — | 串扰假说已被证伪,不必每次三块全刷。面板驱动量约降到 1/3,观感无损 |
| 风扇停转时断 EXT 5V | `FAN_GATE_EXT_POWER`(默认 `1`) | 消除继电器升压电路空耗。上下电顺序:上电**先供 5V 再给信号**,断电**先撤信号再断 5V** |
| CPU 静态降频 | `setup()` 里 `setCpuFrequencyMhz(80)` | 必须在 `Serial.begin()` **之前**调用 |

> ⚠️ **休眠前必须等面板刷完。**`pushCanvas()` 是**异步**的:`UpdateArea()` 只在开头 `CheckAFSR()`
> 等上一次刷完,发出命令后立刻返回,面板还要再驱动 **450~750 ms**(实测)。不等就休眠会把**最后
> 一块**的刷新拦腰切断,表现为该块永远刷不出来。`epdRest()` 因此先 `CheckAFSR()` 再休眠。
>
> 动态调频到更低频率(如 10 MHz)在本平台**行不通**:`CONFIG_PM_ENABLE` 未编入 Arduino 预编译库,
> 且 `CONFIG_SPIRAM_SPEED_80M=y` 要求 APB 锁定 80 MHz,而 canvas 与字体缓存都在 PSRAM 里;
> `esp32-hal-uart.c` 也未注册 APB 变频回调,降频会直接冲垮波特率。
>
> 剩余最大热源是**继电器线圈本身**(约 70–80 mA @ 5V ≈ 0.4 W,比所有软件优化省下的总和还大),
> 要根治需换 MOSFET/固态开关或磁保持继电器。

详细的定位过程、实测数据与踩坑清单见 `~/Documents/md/M5PAPER_EINK_FADE_IT8951_POWER.md`。

## 串口协议

USB 串口,**115200 波特率**。

**上位机 → M5Paper**,每次更新一行(各字段可缺省、按需发送):

```
MEM:<0-100>,MEMG:<GB>,TEMP:<°C>,PWR:<watts>\n
```

- `MEM`  — 内存使用百分比(0–100),驱动 MEMORY 进度条
- `MEMG` — 已用内存(GB),作为 MEMORY 的数值显示
- `TEMP` — 温度(°C),进度条按 20 °C = 0% … 100 °C = 100% 缩放
- `PWR`  — 功率(W),进度条 = 功率(钳制到 0–100)

**环境传感器查询**——发送 `[T]`,设备回复:

```json
{"Temp": 24.3, "Hum": 41.0, "afsr_ms": 742}
```

- `Temp` / `Hum` — 内置 SHT30 读数。注意它贴在主板上,读的是**板温不是室温**,会比环境高出机内温升。
- `afsr_ms` — 诊断字段:上次休眠前等面板刷完花了多少毫秒。设备没有调试口,靠它从主机侧确认刷新
  确实跑完才休眠(`0` 表示还没刷过)。**它只能证明面板被驱动了、时序正常,证明不了画面内容正确**
  ——万一波形表丢失,刷出花屏时这个值照样是正常的。

### 上位机发送示例(Python)

```python
import psutil, serial, time

ser = serial.Serial("/dev/ttyACM0", 115200)
while True:
    vm = psutil.virtual_memory()
    line = f"MEM:{int(vm.percent)},MEMG:{int(vm.used/1e9)},TEMP:0,PWR:0\n"
    ser.write(line.encode())
    time.sleep(2)
```

`TEMP` / `PWR` 请按你的平台改写(例如用 `nvidia-smi` 读取 GPU 温度/功率)。

## 风扇控制逻辑

滞回控制防止继电器抖动:

- **开启**:`TEMP ≥ 60 °C` **或** `PWR ≥ 30 W`
- **关闭**:仅当 `TEMP ≤ 50 °C` **且** `PWR ≤ 20 W`,**并且已持续满 `FAN_OFF_DELAY_MS`(默认 1 分钟)**。
  这段时间内负载任一项再升回关闭阈值以上,计时立即清零重来——所以风扇一旦启动至少运转 1 分钟,
  负载在阈值附近反复波动也不会频繁开关继电器。
- 断连(无读数)时强制**关闭**(不受延时约束,安全优先)。

屏幕上的向上箭头与风扇同步:绘制在仍高于关闭阈值的每一行;最后一个箭头在风扇停转的瞬间消失。风扇
启停会触发立即重绘(无视更新间隔)。

阈值都是 `dashboard.ino` 顶部的 `#define`,可按需调整。

## 编译与烧录

1. 安装 **Arduino IDE** 并添加 ESP32 板支持,选择 M5Paper 开发板。
2. 安装库:
   - **M5EPD**
   - **Adafruit SHT31 Library**(及其依赖 Adafruit BusIO)
3. 打开 `dashboard.ino` 并上传。
